Core · Part 1 of 3

Two kinds of machine

Fixed rules, or learned from data?

Rules vs learning

A rule-based system is like a recipe: a person writes every step and the machine follows them exactly. A Salik toll gate charges you when your car passes – a person set that rule.

A learning system is different. Nobody writes a rule for every case. Instead it is shown many examples – this is data – and it finds the pattern by itself. The pattern it builds is called a model.

Core · Part 2 of 3

Ask sharp questions

What does a real question sound like?

Figure 2 · A good question probes how a system decides

Input: an apple – “Is it a fruit?” The system decides with a rule: IF it is a fruit THEN eat it, ELSE don't eat it. Output: “Eat”. Seeing the output is not enough – a good question asks about the rules or patterns behind the output, not just what it looks like.

Why the kind matters

If you know which kind a system is, you can guess when it might fail. A rule-based system fails when something happens that has no rule. A learning system can fail if it was shown poor or unfair examples.

Neither kind is magic, and neither understands like a person – so a system detective asks sharp questions about how it decides.

Core · Part 3 of 3

Our responsible-use rules

Judge and agree the class charter.

Figure 3 · What makes a strong safe-use rule?

A strong safe-use rule is ① clear (easy to understand and specific), ② keeps data private (protects personal information and shares only what's needed), and ③ can be followed (possible with the tools, time and steps we have).

What makes a good rule

This term we build a class charter for using AI tools responsibly.

A strong rule is clear and can actually be followed – like ‘never put personal data into a prompt’ and ‘always check important outputs against a trusted source’. Some suggestions need work, and some are not safe-use rules at all.

Core mission · Worksheet

System detectives: sort, question, and charter

Be a system detective. Sort three real systems, post the questions you most want answered this term, and help agree one class rule for safe AI use.

Let's try it

  1. Watch the two clips your teacher shows and spot which machine was told every step.
  2. Sort the three cards into ‘fixed rules’ or ‘learns from data’ with your partner.
  3. Write one reason under each card – what is your evidence?
  4. Post at least two genuine questions on the class question wall.
  5. Suggest one responsible-use rule and add it to the class charter.
  6. Read one classmate's question and one charter rule aloud.

No clips? Read the two printed scenario cards aloud and sort using only the cards – the mission runs fully unplugged.

Week 1 Lab

Rule vs Learning – Hands-On Exploration

Today you get your hands on two machines – one that never changes, and one that learns from examples. Watch closely: their differences will jump right out.

Lab: I can…

  • I can run the rule-card machine and the learn-from-examples game and record what each does.
  • I can log at least three differences I observed between them.
  • I can design a fair test that would reveal whether a system follows rules or learns.
Lab · Part 1 of 3

Two stations

One follows cards, one learns a pattern.

Two stations, two behaviours

At Station A the rule cards never change. Feed in the same card twice and you get the same answer twice – that is a rule-based system.

At Station B nobody hands you rules. You study example cards, build a pattern, then use it to sort new cards. That is a learning system in miniature.

Lab · Part 2 of 3

Log the differences

Record how each one behaves.

Figure L2 · A genuine difference is about behaviour

Two red cards (an apple and a strawberry) have the same colour but are different fruits. A banana and an orange look different but follow the same rule – both are fruit. A genuine difference is about how the system behaves, not the colour of the cards.

What counts as a difference

The best detectives don't just watch – they record. Note what each station does with the same input, and how it reacts to something new.

A real difference is about how the machine behaves, not how its cards look. Colour and table size are clues to nothing.

Lab · Part 3 of 3

Design a fair test

A test that reveals rules or learning.

Figure L3 · A fair test

Give both machines the same strange input – same input, same chance – then record exactly what happens at each machine and compare the results fairly.

Design a fair test

To tell the two apart, give each machine a brand-new, unusual input. A rule-based machine reacts the same as always or simply stops. A learning system tries to match the pattern it built.

Before you start, write down exactly what you will try and what each result would mean. That is what makes the test fair.

Lab mission · Worksheet

System detectives: two stations, one fair test

Run a fixed rule-card machine and a learn-from-examples card game, log what changes, then design a test that reveals which kind an unknown machine is.

Let's try it

  1. Take a role: feeder, recorder or tester.
  2. At Station A, feed five inputs through the rule cards, including one strange one, and log each output.
  3. Note whether Station A ever changed how it behaved.
  4. At Station B, study the example cards and agree a pattern as a group.
  5. Sort five new cards using only your pattern; log your guesses and the correct answers.
  6. Record at least three differences between the two stations.
  7. Design one test that would reveal whether an unknown machine follows rules or learns.

No printed cards? Run both stations by voice – the teacher reads fixed if-then rules for Station A and describes example items aloud for Station B while you classify by ear. Example cards show shapes and objects only – no faces or names.

Lesson summary

You launched the unit, investigated two machines by hand, and learned to test which kind you are facing

Key ideas to remember

  • A rule-based system follows steps a person wrote; it repeats itself (same input, same output) and fails when a case has no rule.
  • A learning system builds a model from examples (data); it can guess wrongly on very different cards, or if the examples were poor or unfair.
  • Neither kind is magic or understands like a person – always check what a machine tells you.
  • A genuine difference is about behaviour, not how the cards look.
  • A fair test gives a brand-new input and decides in advance what each result would mean.
  • A strong responsible-use rule is clear, keeps data private, and can be followed.

Glossary

Rule-based system
a system that follows fixed steps written by a person.
Learning system
a system that finds patterns in data instead of following written rules.
Data
the examples a learning system is shown.
Model
the pattern a learning system builds from its data.
Fair test
a planned test where you decide what each result will mean before you start.
