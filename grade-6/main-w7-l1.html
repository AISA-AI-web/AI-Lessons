Core · Part 1 of 3

One whole solution

What are the five parts of a plan?

Previously

Last week you put all four strands together in one build-and-check task. In Grade 5 you improved a single prompt. Now you design a whole signature solution – and you plan it on paper before anyone types a word into an AI tool.

From one prompt to a whole solution

In Grade 5 you improved a single prompt. This term you design a solution: a set of parts that work together to do one simple job well.

The five parts are the goal, the prompt structure, the inputs, the evaluation method and the risk plan. If any part is missing, the solution is harder to trust. A good plan is like a bridge design drawn before the first bolt – it lets you find weak spots on paper, where fixing them is cheap.

Core · Part 2 of 3

The prompt structure

What does a prompt structure name?

Writing a prompt structure

A prompt structure names a role (“You are a timetable helper”), a task (“list the three earliest buses”) and one rule (“if a time is missing, say so”).

The role focuses the AI, the task says exactly what to do, and the rule keeps the output honest and easy to check.

Core · Part 3 of 3

Checks and risks

Which choices make a plan strong and safe?

Checks and risks before you build

An evaluation method says how you will judge accuracy, such as comparing the output to a known-correct answer key.

A risk plan names one thing that could go wrong, like a confident wrong answer, and one design choice that reduces it, like a “say if unsure” rule plus a human check. Never put personal or identifying data into a prompt.

Core mission · Worksheet

Design your signature solution plan

Plan your own signature solution on the plan sheet. Your job is to make the plan complete and safe.

Tool for this week: plan sheet and curated output cards (teacher-led)

You will not log in to any tool – the teacher runs any AI on the board. Never put personal or identifying data into a prompt. No tool? Work entirely on planning cards using curated sample outputs pinned to the board – the plan is complete without any live AI.

What you need: a signature solution plan sheet, a task card, role-task-rule cards, curated output cards and a pencil.

Let's try it

  1. Read your task card and write the goal in one clear sentence.
  2. Fill the role, task and rule slots for your prompt structure.
  3. List the inputs your prompt needs, checking there is no personal data.
  4. Write your evaluation method – how you will check accuracy.
  5. Name one risk and one way your plan reduces it.
  6. Self-check against the five-part list, then submit for the approve-to-build gate.
Week 7 Lab

Prototype and Pressure-Test the Plan

A plan on paper looks tidy. Today you find out how it behaves under pressure – the way engineers stress-test a bridge before anyone crosses it.

Lab: I can…

  • I can run my prompt structure on a normal input and read the output.
  • I can pressure-test it with a tricky input and spot where it fails.
  • I can add a fallback branch that says what to do when a check fails.
  • I can record the change I made and the reason for it.
Lab · Part 1 of 3

Prototype first

Build it fast, then judge what it really does.

Prototype, then judge

A prototype is a fast first version of your solution. You build it quickly so you can watch how it really behaves, instead of guessing.

The teacher runs your prompt structure on the board with a normal, curated input. You read the output and decide one thing: did it meet the goal? Only curated, made-up inputs are used – never real names or personal data.

Lab · Part 2 of 3

Pressure-test

Which inputs make the prototype stumble?

Throw the hard inputs

Pressure-testing means feeding your design its hardest inputs on purpose: the missing value, the messy note, the two-in-one line. These edge cases reveal weak spots that a normal input hides.

A clean, ordinary input usually holds up. A tricky curated input is more likely to break the prototype – and that is exactly what you want to find before the solution is trusted.

Lab · Part 3 of 3

Design a fallback

What should happen when a check fails?

Plan the safe branch

When a check fails, a good solution follows a fallback branch instead of giving a confident wrong answer. Write it as ‘If the check fails, then ___ and ask a person.’

Keeping a human in the loop is part of responsible design. Some fallback ideas are strong, some need work, and some are not safe fallbacks at all – so judge each one before you log the change and your reason.

Lab mission · Worksheet

Prototype, stress-test, and catch the failure

Turn your approved plan into a working prototype, throw curated tricky inputs at it on the board, and design a fallback branch that catches the failure. Log every run.

Tool for this week: Build/Test Log and curated cards (teacher-led)

The teacher runs the prototype on the board – no logins. Only curated, made-up inputs are used – never real names or personal data. No live tool? Lay the plan out on cards and use curated output cards as the ‘AI response’; a partner reads the card so pairs can pressure-test and design a fallback fully unplugged.

What you need: a Build/Test Log (two columns), curated tricky-input cards, curated output cards and a pencil.

Let's try it

  1. Copy your approved prompt structure into the prototype slot of your log.
  2. Watch the normal-input run on the board and record whether it met the goal.
  3. Pressure-test with a tricky curated input and record the error type: wrong, unclear or missing.
  4. Write a fallback branch as ‘If the check fails, then ___ and ask a person.’
  5. Re-run on the tricky input if there is time and log the one change you made.
  6. Note the reason your change will help next week.
Lesson summary

You designed a whole solution on paper, then turned it into a prototype and hardened it under pressure

Key ideas to remember

  • A signature solution is a small system with five parts, not a single prompt.
  • The five parts are the goal, the prompt structure, the inputs, the evaluation method and the risk plan.
  • A prompt structure names a role, a task and one rule to keep the output honest.
  • A strong plan names one risk and one design choice that lowers it, and keeps personal data out of the prompt.
  • A prototype is a fast first version – running it shows how the design really behaves.
  • Pressure-testing feeds a design its hardest inputs on purpose to expose weak spots.
  • A fallback branch is a planned safe response that keeps a person in the loop. Log the one change you made and the reason it will help.

Glossary

Signature solution
a small, reusable design that fits five parts together to do one job well.
Prompt structure
a role, a task and one rule that guide the AI.
Evaluation method
how you will judge whether an output is accurate.
Risk plan
one risk you name and one design choice that reduces it.
Prototype
a fast first working version you build to see how a design behaves.
Pressure test
trying a tricky input on purpose to find where a design fails.
Fallback branch
a planned response for when a check fails, such as label it and ask a person.
Edge case
a hard, unusual input like a missing, messy or double value.
