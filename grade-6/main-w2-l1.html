Core · Part 1 of 3

Two features

Where does the logic come from, and how does it meet the new?

Previously

In Week 1 you sorted machines into ‘follows fixed rules’ and ‘learns from data’. Now you learn the two features that prove which kind a system is.

Words to know

Tap a card to flip it and reveal the meaning.

Two features that decide it

Feature one – where does the logic come from? In a rule-based system a person writes it. In a learning system it comes from data.

Feature two – what happens with something new? A rule-based system only handles cases its rules cover. A learning system can handle new cases that look like its examples.

Core · Part 2 of 3

One example each

Classify everyday systems by feature.

One example of each

Once you know the two features, you can classify almost any system you meet. Ask where the logic came from, and whether it can handle a new case.

A metro gate follows fixed rules a person wrote. A voice assistant that improves as it listens learned its pattern from data.

Core · Part 3 of 3

Say it right

Use data and model correctly.

Data is not the model

Be careful with words. The data is the examples. The model is the pattern built from them. Change the data and you can change the model.

A learning system does not understand meaning – it matches patterns. So always check its answers.

Core mission · Worksheet

System detectives: build the feature chart

Build a two-column feature chart, then use it to classify everyday UAE systems – defending each choice with a feature, not a shiny screen.

Tool for this week: feature chart and everyday-system cards (unplugged)

You need the feature-chart handout, the everyday-system cards and a pencil – no devices and no logins. No cards? Classify systems your class names aloud – a metro gate, a photo app that groups pictures, a voice assistant – using only the feature chart.

Let's try it

  1. Copy the two-column feature chart: where the logic comes from, and how each system meets something new.
  2. Add one example to each row with your partner.
  3. Classify two everyday systems using the chart.
  4. For each, underline the feature that decided your answer.
  5. Write two sentences that use data and model correctly.
  6. Share one classification and name the feature that proved it.

Words to know

Tap a card to flip it and reveal the meaning.

Lab · Part 1 of 3

Train, then test

Learn from one set, check on another.

Train, then test

First you show the model many labelled training examples. It finds the pattern and builds a model.

Then you test it on new examples it has never seen. If it still gets them right, it really learned. If not, it only memorised.

Lab · Part 2 of 3

Keep data safe

Only non-personal examples.

Keep your data safe

Golden rule: only non-personal examples. No faces, no voices and no names ever go into a training set.

Safe examples are things like shapes, objects and simple drawings. Personal data must always stay out.

Lab · Part 3 of 3

Examples shape it

Your choices decide what it learns.

Your examples shape the model

If all your apple pictures are red, the model learns ‘red’, not ‘apple’, and fails on a green one. Variety and fairness matter, not just how many.

That is why you test on fresh examples – to check the model truly learned the pattern instead of just memorising.

Lab mission · Worksheet

System detectives: train and test a model

Build a training set of safe, non-personal examples, train a simple model, then test it on new examples and run a data-safety check.

Tool for this week: a paper classifier (no digital tool needed)

You need labelled non-personal example cards (objects, shapes, drawings), a decision-chart or paper-classifier sheet, a results log and a pencil. Build a decision chart from your training cards and classify the held-back cards by hand – the same learning, with no devices. Stay safe: only non-personal examples – never faces, voices or names, in the training set or the testing set.

Let's try it

  1. Choose two categories of non-personal items, such as dates versus dried lemons, or circles versus triangles.
  2. Collect and label 8–10 clear training examples per category.
  3. Set aside 3 testing examples per category and keep them hidden.
  4. Train your paper classifier using the training examples only.
  5. Predict, then test each held-back example and log correct or incorrect.
  6. Explain how your training examples shaped what the model learned.
  7. Run the data-safety check, then write one way to improve your training set.
Lesson summary

You turned the difference into two clear features – then trained a model by hand and saw how your examples shape it

Key ideas to remember

  • Feature one: where the logic comes from – a person writes it, or it is learned from data.
  • Feature two: how it meets something new – rules only cover their cases; learning can handle new cases that look like its examples.
  • The data is the examples; the model is the pattern built from them. A learning system matches patterns – it does not understand meaning – so always check its answers.
  • Train on one set of examples, then test on new ones to check it truly learned. Passing only the training examples might mean it just memorised.
  • Your examples shape the model: red-only apples teach ‘red’, not ‘apple’. Variety and fairness matter.
  • Golden rule: only non-personal examples – never faces, voices or names.

Glossary

Rule-based system
a system whose logic a person writes as fixed steps.
Learning system
a system whose logic is learned from data as a model.
Data
the labelled examples a learning system learns from.
Model
the pattern a learning system builds from its data.
Training set
the examples a model learns from.
Testing set
new examples used to check if the model really learned.
Data safety
using only non-personal examples – no faces, voices or names.
