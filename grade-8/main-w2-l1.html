Inside the Pipeline + Change One Factor

Every AI tool you use turns an input into an output using a model in the middle. Today you open up that shape so you can explain – and later judge – how any tool works. Then, in the Lab, you become the tester: build a small system, change one factor at a time, and work out why the output moves.

Input, model, output

Look inside almost any AI tool and you find the same pipeline. First an input goes in – text, an image or a sensor reading. Then a model changes it – this is the part you cannot see, and it learned its behaviour from many past examples. Last, an output comes out – a label, a prediction or something new.

During one prediction the arrows only point one way, so the order of the stages matters for that single run. This does not mean building AI is linear: developing a model is a loop. Teams test the outputs, evaluate them against criteria, and feed what they learn back to improve the data, the workflow or the model – then retrain and run again. One prediction runs forward; development runs in repeated testing, feedback and retraining cycles.

Core · Part 2 of 3

Each part's job

Which stage does which work?

Trace a worked example

Tracing means following one item of data through each stage and naming what happens to it. Once you can name the stages, you can explain how a tool works – from a photo filter to a translation app. Each part has one job: the input is the data that goes in, the model is the trained process that turns it into a likely output, the output is what comes back, and the pipeline is the stages joined in order.

Why it matters

AI services across the UAE – from Arabic-English translation apps to smart-parking sensors and traffic-flow tools – all follow the input-model-output pipeline. (Illustrative examples.) Knowing the shape lets you understand, question and improve the tools around you.

Cross-curricular link · Computing

In Computing, draw the input-model-output pipeline as a flowchart – the same ordered-step diagrams used for algorithms – and trace one data item through each box to explain how an input becomes an output, just as you would dry-run a program.

Core · Part 3 of 3 · Worksheet

The model is not magic

So can you trust every output?

The model stage can feel like magic, but it is not. Inside, it has learned patterns from many past examples, and it uses those patterns to turn your input into a likely output. It does not think or understand – it predicts. That is why an unusual or unclear input can lead to a strange output, and why the same model behaves differently as its input changes. Knowing this is the first step to evaluating a system: you check the output instead of trusting it, and you look for the stage that shaped the result.

Tool for this week: unplugged simulated-AI cards (teacher-led)

The teacher runs a simulated-AI card routine on the board – no live tool, no logins. A ‘model’ envelope holds a fixed rule; post an input card in and it returns the matching output card. Students reason about the pre-prepared outputs (no personal data), sort the cards as input, process or output, and explain their thinking with the key vocabulary.

Lab · Part 1 of 3

Traceable vs black box

Which system can you actually explain?

A structured workflow is more explainable than a single black-box model. Because each step is separate, you can trace any output back to the exact step that produced it and say why that step gave that result. A black box only shows its input and output, so you cannot see why it decided as it did. Being able to trace outputs to steps is what makes a system auditable and trustworthy – a real design advantage. Real AI research calls this explainable AI (XAI).

Lab · Part 2 of 3

Trace one item

How do you keep a test honest?

Tracing means picking one item and following it all the way through the pipeline. You watch it go in as the input, see what the model turns it into, and read what comes out as the output. Writing down each stage for the same item keeps you honest – it stops you mixing up two different items. A clear trace is how testers prove they know what a system really does, not just what they hope it does. It is also the record you compare against when you start changing factors.

Why it matters

Testers who change factors on purpose find problems before real users do. This is how teams in the UAE check an AI service performs fairly – across different inputs and data – before it is switched on for the public.

Cross-curricular link · Science

This is a fair test from Science: change one factor – the input or the example data – while keeping everything else the same, then compare outputs to find the cause, recording the changed variable exactly as in a controlled experiment.

Lab · Part 3 of 3 · Worksheet

Change one factor, compare and verify

Which change is a fair test?

Here is the tester's method: keep everything the same except one factor, then run it again and compare. Change only the input, or swap the example data the model learned from, and watch the output. If the output moves, that factor affects performance. Some factors move the output a lot, others barely at all – that is exactly what you are trying to find out. Before you trust any output, verify it against something you know is correct.

Same model, or a new one?

If you change only the input, the model is not retrained – it is the same model, given different evidence. If you change the training examples and train again, you get a new, retrained model.

Today's tool: Google Teachable Machine – train, test, measure (teacher-operated)

1. The teacher names three classes and adds about 15 balanced, varied example images to each (objects or hands only). 2. Train – the examples are the training data, training builds the model, a prediction is the output. 3. Run held-back test examples the model has never seen, one by one, and record correct or wrong. 4. Count the score (e.g. 7 out of 10) – your first accuracy measure. 5. Discuss where it failed, change one factor, retrain and compare. Stay safe: the teacher operates the tool and students never log in; use objects, hand gestures or drawings only – never faces, voices or names; clear the project at the end of the lesson. No device? Run a card-deck ‘human classifier’ and tally hits and misses on 10 new cards.

Lesson summary

Open the pipeline – then change one factor and verify

  • Almost any AI tool is a pipeline: input, model, output.
  • For one prediction the arrows point one way, but development runs in a loop – test, evaluate, improve, retrain.
  • The model predicts from learned patterns – it does not think or understand – so check the output.
  • A traceable workflow is more explainable and auditable than a black box.
  • Trace one item through, then change one factor at a time so you know what caused the output to move.
  • Changing the input keeps the same model; changing the training examples gives a new, retrained model. Before trusting any output, verify it against a trusted answer.
