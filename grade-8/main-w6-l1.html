Nothing new, all at once

Until now you have practised four skills in separate lessons: understanding how a classifier works, building the steps, evaluating an output, and using AI responsibly. Today they click together on a single model. You set a target, run a test set whose answers you already know, score how many the model got right, and compare that score with the target.

Nothing here is brand new – you are using all four skills at once, which is exactly how real AI solutions are judged and improved. Joining several skills into one working task is called integration.

Core · Part 2 of 3

A score you can trust

Why does the test set matter?

Sure is not correct

A classifier gives every date a label, and it can sound very sure. Sure is not the same as correct. That is why the test set matters: because you already know the true label of each card, you can mark every prediction right or wrong and count the accuracy. Then you compare that accuracy with the performance criterion – the target the model must reach, such as eight correct out of ten.

If the score misses the target, you look at which kind of date failed most and add one rule aimed at that, then re-test to see if the score rises.

Why it matters

Across the UAE, date growers and sorting lines are trialling classifiers to grade fruit quickly – and they only help if their accuracy is tested against a clear target and their data is handled responsibly, just like in your task. (Illustrative example.)

Cross-curricular link · Mathematics

In Mathematics, express the model's score as a fraction and percentage (8 out of 10 = 80%) against the 80% target, then break the ten results down by date type to find which category scores lowest.

Core · Part 3 of 3 · Worksheet

Find and fix

Is the overall score the whole story?

An overall accuracy score can hide a weak group. Error analysis asks which kind of date the model gets wrong most, so your improvement is aimed rather than guessed: add one rule aimed at that group, then re-run those cards and see if the score rises. You keep the task safe by using only fruit photos – never a person's face – so evaluating and improving stay responsible from the start.

Tool for this week: unplugged simulated-AI cards (teacher-led)

This is an unplugged concept lesson: the teacher runs a simulated-AI card routine on the board – no live tool, no logins. Students reason about pre-prepared example outputs on the cards – no personal data is used – and use the worksheet to sort or judge the cards, explaining their thinking with the key vocabulary. No board tool? The cards already carry true labels on the back – score the ten by hand, which is the same test, score and improve routine. The live tools (Teachable Machine and Scratch) are used in the matching Lab period.

Lab · Part 1 of 3

From one card to a full test

How do you turn a run into evidence?

In the Core lesson you scored the model on a few cards. Today you run it end-to-end on twelve or more, and you write down every score in a results log. That log is powerful: it turns ‘it seemed to work’ into real evidence. You can total how many predictions were right, compare that with the criterion, and spot patterns – maybe dark ripe dates trip it up most.

Lab · Part 2 of 3

Evidence, not a feeling

What makes a reliability claim trustworthy?

Your log lets you total how many predictions were right and compare that with the criterion. That total is your model's reliability, and it tells you exactly how far it is from the target and where to aim your improvement. A reliability claim is only trustworthy when it comes from the recorded scores – not from a feeling that the model seemed accurate today.

Why it matters

Date growers and sorting lines in the UAE keep improving their grading systems by logging errors and testing each change against a clear target – exactly the run, evaluate and improve loop you are practising today. (Illustrative example.)

Cross-curricular link · Geography

Mirror a Geography fieldwork log: tabulate repeated observations across many trials, then compare the ‘before’ and ‘after’ of one method change to spot which conditions, such as time of day, produce the most errors.

Lab · Part 3 of 3 · Worksheet

Add a constraint, then re-test

How do you improve without starting over?

A real model rarely stays the same – you improve it as you learn. Today you make one aimed change, then add one constraint: either a second criterion, like also labelling each date bruised or not, or a risk rule, like flagging any date that might be mouldy. Then you re-score only the cards the new rule touches and check your accuracy before against accuracy after. Notice you do not start over – you adapt the model you already have. This cycle of test, analyse errors, change one thing and re-test is called iteration. All the while you keep the safe rules: only fruit photos go in, and every prediction is verified against its true label before you trust it.

Today's tool: Teachable Machine + Scratch – build, evaluate, improve loop (teacher-operated)

1. Train the model in Teachable Machine: name the classes, add balanced examples, click Train, then test in Preview. 2. Open Scratch (account-free) and add the machine-learning blocks so the trained model becomes the process step. 3. Wire the workflow: input (what you feed in) → model (classifies) → output (what Scratch shows), and click the green flag to run it end to end. 4. Run five inputs and record the outputs; evaluate them against the criteria and score them. 5. Make one improvement (add cleaner examples, or add a check in Scratch), re-run the same five inputs and re-score. Save the Scratch project as an .sb3 file. Stay safe: the teacher operates the tool on the board and students never log in; Teachable Machine trains in the browser and the samples stay on the teacher's device; use objects, hand gestures or drawings only – never faces, voices or names; clear the project at the end of the lesson; reuse only the non-personal model. No board tool? Run the whole test set by hand against the true labels – the same end-to-end evaluation, results log and re-test.

Lesson summary

Join the four strands – then run it end to end and prove the change

  • Integration means all four strands – understand, build, evaluate, use responsibly – act on one task at once.
  • A test set with known answers lets you count real accuracy and compare it with a target.
  • Sure is not correct – a confident label must still be checked against the true label.
  • Error analysis aims your improvement at the group that fails most.
  • Running end-to-end scores every item, and a results log turns ‘it seemed to work’ into counted evidence of reliability.
  • You adapt the model and re-test what changed – you do not start over – and you keep the safe rules: fruit photos only, no faces, voices or names.
