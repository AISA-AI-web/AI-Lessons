Design the Workflow + Build, Test, Improve

Today you stop treating AI as a magic box and start designing a real solution – a clear chain of steps that solves one specific task and that you can actually check. Then, in the Lab, you build it fully and stress-test it – because a solution you can trust is one you have tried to break and then improved.

Strand: AI Solution Design  ·  Role: AI Evaluators

What you will learn

  • Design a workflow. I can define a specific task and design a simple AI-powered workflow to solve it.
  • Build it step by step. I can build my workflow step by step and explain why each step is there and what it produces.
  • Use the words. I can use words like input, process, output and workflow correctly to describe my solution.
  • Lab: build, test, improve. I can run more than one sample input through my workflow, spot which step causes a wrong output, change that step to improve the result, and describe my testing and my fix with the correct vocabulary.

A chain, not a guess

A solution is a chain

An AI-powered solution is not one clever reply – it is a workflow: an ordered chain of steps that turns an input into a useful output. You start with a task, choose an input, run a process step that transforms it, get an output, and then check that output.

Because the steps are laid out in order, you can run an example through and see exactly what each box does. If something goes wrong, you can point to the box that caused it – and that is what makes a solution something you can trust and improve, instead of a guess you just hope is right.

Core · Part 2 of 3

Design, then build

Which box does which job?

Design safely first

Good design happens before building. You decide the one specific task, then the input – and you only ever use non-personal sample data, never real names, faces or voices. The AI step in class is simulated or teacher-run and needs no account, so you can focus on the shape of your solution.

Each box has one job: the task says what you are solving, the input is what you feed in, the process step transforms it, and the check verifies the output before you rely on it.

Why it matters

Across the UAE, teams building tools like smart-city waste sorting or Arabic-English translation services succeed because they design tested, traceable workflows – the same skill you are practising today, at classroom scale. (Illustrative examples.)

Cross-curricular link · Art & Design

Designing a five-step workflow for one specific task mirrors the Art and Design process: write a clear design brief, plan the stages, make it, then evaluate against the brief – including a built-in check step before the work counts as finished.

Core · Part 3 of 3 · Worksheet

The check box

So can you trust a confident output?

The most important box is the check. A confident-looking output can still be wrong for your task, so you always compare it against the task and a trusted source before you rely on it. That single box is what turns a guess into a solution you can defend.

Using the words input, process, output and workflow correctly helps you say exactly where a problem could enter – and which box you would change to fix it.

Tool for this week: unplugged simulated-AI cards (teacher-led)

This is an unplugged concept lesson: the teacher runs a simulated-AI card routine on the board – no live tool, no logins. Students reason about pre-prepared example outputs on the cards – no personal data is used – then sort, match or sequence the cards as input, process or output and explain their thinking with the key vocabulary. No cards? A partner plays the ‘model’, returning a fixed labelled response, so the workflow can still be built and traced with no device. The live tools (Teachable Machine and Scratch) are used in the Lab.

Lab · Part 1 of 3

One pass is not proof

Does one correct output mean the solution works?

A workflow that gets one input right might still be unreliable. Real testing means running several sample inputs, including a tricky or ambiguous one, and watching for where the output fails the task.

Each failure is useful: because your workflow is an ordered chain, a wrong output can be traced back to the exact box that caused it. So instead of hoping your solution works, you find out where it breaks – and that is the first step to making it something people can actually depend on.

Lab · Part 2 of 3

Change one step

How do you actually improve a solution?

Improving a solution does not mean starting again. You find the box causing the most failures – maybe the input you chose, the process step, or the check – and you change just that one step.

Then you run the same sample inputs again to see whether the output really improved. Keeping everything else the same is what lets you tell if your fix actually helped. The AI step stays simulated and account-free, and every input is non-personal, so all your effort goes into building, testing and improving the workflow itself.

Why it matters

Engineers on UAE projects – from Arabic speech tools to smart-logistics routing – ship reliable products by testing against many cases and fixing the exact step that fails, which is precisely the build-test-improve loop you run today. (Illustrative examples.)

Cross-curricular link · Physical Education

Iterating a workflow works like refining a skill in PE: change one part of your technique, such as your grip, then repeat the exact same drill and measure whether results improved – altering only one thing so you know what helped.

Lab · Part 3 of 3 · Worksheet

Trace the failure

Which box is responsible for a wrong output?

Because your workflow is an ordered chain, every wrong output has a failing step – the single box responsible. The symptom often tells you which box: unclear results in point to the input, wrong labels point to the process step, and a bad output slipping through as fit points to the check.

A solution is reliable when it passes a range of inputs, not just one. Describing your testing and your fix with the right words is what lets someone else follow your reasoning.

Lesson summary

Design the chain – then build it, break it and improve it

  • A solution is a workflow: task, input, process, output, check – in order.
  • Design safely first: one clear task and a non-personal input, before building.
  • Each box has one job, so you can trace any error back to the box that caused it.
  • The check box verifies the output against the task and a trusted source – a confident output can still be wrong.
  • One passing input is not proof – test several, including a tricky one, and find the failing step.
  • Iterate by changing one step, then re-running the same inputs. A reliable solution passes a range of inputs, not just the easy ones.
