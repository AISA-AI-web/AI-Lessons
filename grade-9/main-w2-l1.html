Understanding the System + Test the System

Every AI tool turns an input into an output, but never with a single part. Today you open a system up and see its components – the data, the tool and the prompt – interact, so you can explain, and later judge, how any solution works. Then, in the Lab, you become the tester: build a small system, change one component at a time and work out which interaction moves the output.

Strand: AI Systems Understanding  ·  Role: Solution Architects

What you will learn

  • Input to output. I can describe how an AI system turns an input into an output and name the components that interact to do it.
  • Map a worked example. I can investigate a worked example, map the input to the output, and explain the reasoning to a partner.
  • Use the words. I can use words like component, data, tool and prompt correctly, and say how their interaction helps me build or evaluate a solution.
  • Lab: test the system. I can trace one input through a system's components, change one component and compare the two outputs, justify which component most affected the output, and say how I would verify it against a trusted source.

A system of parts

What does an input flow through?

Previously

Last week you changed one part at a time and traced each output difference back to its cause. What is new this time: you follow one input's flow through the parts, and see how the data limits the tool while the prompt steers it.

Words to know

Tap a card to flip it and reveal the meaning.

A system is components that interact

Look inside an AI tool and you do not find one box – you find components working together. There is data the tool learned from, the tool that applies those patterns, and the prompt that steers it on this occasion. An input flows through all of them and an output comes out the other end. The parts interact, which means each one affects the next: the data shapes what the tool can do, and the prompt shapes what it does right now. Once you can see the components, you can explain how a solution works.

Core · Part 2 of 3

Follow the interaction

How does each part shape the next?

Analysing, not listing

Describing a system is more than naming parts – it is following how they interact to make the output. Ask what the input was, what the data let the tool learn, how the prompt steered it, and why that produced this result rather than another. This is analysing, not just listing. When you can trace the interaction, you can say which component shaped the output most, and that is the first move a designer makes before improving a solution. It is also why you check an output instead of trusting it.

Why it matters

AI services across the UAE – Arabic-English translation apps, smart-parking sensors, hospital triage helpers – are all systems of interacting components. Knowing how the data, the tool and the prompt work together lets you understand, question and improve the solutions around you.

Cross-curricular link · Computing

Dry-run a short algorithm the way you trace an AI system: follow one input step by step through each instruction to the output, then reason about which step shaped the result most, instead of treating the program as one magic box.

Which shaped it most?

Can you trust the output straight away?

Reason, then verify

When you can trace the interaction, you can reason about which component shaped the output most – the data, the tool or the prompt. That is the first move a designer makes before improving a solution, and it is what lets you use the vocabulary precisely. It is also why you check an output against a trusted source instead of trusting it straight away.

Solution Architects: map the interaction (away from the screen)

Name the components in between – the data, the tool and the prompt – and draw arrows showing how one fed the next until the output appeared. Week 2 Lab

Test the System

You already know a system is interacting components – the data sets what a tool can do while the prompt steers each single run. Today you become the tester: build a small system, then change one component at a time and work out which interaction moves the output.

Words to know

Tap a card to flip it and reveal the meaning.

Lab · Part 1 of 3

Trace one input

How do you prove what a system does?

Follow one input through

Tracing means picking one input and following it through the whole system. You watch the data set what the tool can do, see the tool apply it, notice how the prompt steers it, and read what comes out. Writing down each component for the same input keeps you honest – it stops you mixing up two different items. A clear trace is how a tester proves they know what a system really does, not just what they hope it does. It is also the record you compare against when you start changing components.

Why it matters

Testers who change components on purpose find problems before real users do. This is how teams in the UAE check an AI service performs fairly – across different data and prompts – before it is switched on for the public.

Lab · Part 2 of 3

Change and compare

Which change is a fair test?

One change, then compare

Here is the tester's method: keep everything the same except one component, run it again, and compare. Change only the prompt, or swap the data the tool learned from, and watch the output. If the output moves, that component and its interaction affect performance. Change one thing at a time so you know what caused the change. In Teachable Machine you train with data version A, then a richer version B, and run the same held-back test set on both to see which data component gave better outputs.

Cross-curricular link · Mathematics

Swapping the data component is a lesson in sampling and statistics: compare the accuracy (percentage correct) of a model trained on balanced versus unbalanced example sets, and see how an unrepresentative sample skews results.

Lab · Part 3 of 3 · Worksheet

Justify and verify

Which component mattered most?

Evidence, then trust

Some components move the output a lot, others barely at all – and justifying which one matters most is the analysis a designer needs. To justify is to give evidence for a claim, such as your side-by-side comparison. Before you trust any output, verify it: check it against something you know is correct.

Tool for this week: Teachable Machine (see the components interact)

Test in Preview with a new example the model has not seen and read the confidence bars. 6. If it is wrong, add better or more examples, keep the classes balanced, and re-train. Lesson summary

See the components interact – then test which one moves the output

  • An AI system is interacting components: data, a tool and a prompt, not one box.
  • The data sets what the tool can do; the prompt steers what it does this time.
  • Describing a system means analysing the interaction, not just listing parts – then you can say which component shaped the output most.
  • Tracing follows one input through every component and records what each does.
  • Change one component at a time and compare on the same held-back examples; some components move the output a lot, others barely – justify which matters most.
  • Verify every output against a trusted source before you trust it.
