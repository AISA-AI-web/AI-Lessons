Building a Workflow + Test, Fix and Chain

Today you become a builder. You take a task and build a small AI workflow – input, process, output – that gets it done, then test whether it really works. Then, in the Lab, you fix your build's weakest step and grow it into a multi-step workflow that does more than one job.

Core · Part 1 of 3

Steps in order

What does it mean to build one?

Words to know

Tap a card to flip it and reveal the meaning.

Building means putting steps in order

A workflow is just steps in the right order. To build one you decide three things: what goes in (the input), what happens in the middle (the process, done by the AI), and what should come out (the output). The order matters – each box feeds the next one, so if you swap two boxes the workflow breaks.

When you build, you are not making the AI from scratch. You are arranging the steps so the AI step has good input and gives a useful output.

Core · Part 2 of 3

Simulated vs real

Which part is a stand-in?

Our simulated model vs a real trained model

In these lessons the ‘AI step’ is often a paper lookup table or a pre-made card. That is a simulated model: it can only answer items already written on the table.

A real trained model is different – it learns patterns from many examples and can then generalise, giving a sensible answer to an input it has never seen before. Generalising to unseen inputs is the difference. When you design your build, know which part is real AI and which part is a stand-in.

Why it matters

Across the UAE, people use AI workflows to sort emails, plan deliveries and check documents. Learning to build and test one now means you can shape these tools instead of just using them.

Core · Part 3 of 3 · Worksheet

Test before trusting

Is the first output a fact?

A good builder tests before trusting

The first output is a draft, not a fact. Even when the AI sounds sure, it can be wrong. So a good builder runs the workflow, then verifies: does the output match the task, and does a trusted source agree?

If not, you go back and fix a box – maybe the input was unclear. You also try a slightly different input to see if the workflow still works. Testing twice is how you know your build is reliable, not just lucky.

Think about it

If two people gave your classifier the exact same input, it should give the same output every time – a classifier is deterministic. What could make their outputs differ – a different input, a different rule, or using a generative tool that samples instead?

Cross-curricular link · Computing

In Computing, an algorithm is an ordered sequence of steps, and swapping two steps breaks it – exactly like the three-box input-process-output workflow here. Write the steps for a task, then check each one feeds the next in the correct order.

Hands-on mission · Systems Detectives: build and test a workflow

Tool for this week: unplugged simulated-AI cards (teacher-led)

This is an unplugged concept lesson: the teacher runs a simulated-AI card routine on the board – no live tool, no logins. You reason about pre-prepared example outputs on the cards, and no personal data is used. Sort, match or sequence the cards and explain your thinking with the key vocabulary. The live tool (Scratch) is used in the Lab.

In pairs, build a small three-box input-process-output workflow that completes one real class task, using card-based simulated AI so no accounts or devices are needed. You need: a three-box workflow strip, a task menu card, a simulated-AI process card deck, a trusted answer key and a pencil.

  1. Choose one task from the menu, such as sorting six book titles into fiction and non-fiction.
  2. Write your input in the first box – exactly what you will give the workflow.
  3. Place the AI process card that matches your task in the middle box.
  4. Draw the output the cards give you in the third box.
  5. Run it again with a slightly different input and compare the two outputs.
  6. Verify each output against the answer key, then tick or fix each box.

🧰 No card deck? Go fully human: one student acts as the process and silently sorts the inputs by a rule the pair wrote, while the others check the output.

Local connection · AI in the UAE

Abu Dhabi's smart traffic systems take inputs (sensors and cameras), run a process (predicting traffic flow), and produce outputs (signal timings) – a real workflow you can map.

Week 3 Lab

Test, Fix and Chain

In the Lab you get real build time. You test the workflow you made, fix its weakest step, then grow it into a multi-step workflow that does more than one job.

Words to know

Tap a card to flip it and reveal the meaning.

Why it matters

Real UAE workflows – checking passport photos, routing customer messages, planning deliveries – are almost always multi-step and are tested before anyone trusts them. Building and testing a chain now is exactly this skill in miniature.

Lab · Part 1 of 3

Change one thing

How do you improve a build?

Improve by changing one thing at a time

The fastest way to improve a workflow is not to redo it all. You test it, find the one box that weakens the output – often the input – and change only that. Then you run it again and compare.

If you change two boxes at once and it works, you will not know which change helped. Keeping notes of before and after turns guessing into evidence. This is iteration: a small, controlled loop that makes your build better and lets you explain exactly why.

Cross-curricular link · Physical Education

In PE, a relay baton hand-off passes one runner's finish to the next runner's start – exactly like chaining two workflow steps, where one output becomes the next input. Athletes also improve by changing one part of their technique at a time – the same one-change iteration.

Lab · Part 2 of 3

Chain the steps

Where do steps join?

Chain steps to do more

A multi-step workflow does more than one job by chaining steps. The output of the first process becomes the input of the second – that join is the hand-off. It only works if the first step gives the second step something it can use.

So when you test a chain you check two things: does each step complete, and does the hand-off hold? A workflow is reliable when it completes the task for more than one input, so always test with at least two.

Lab · Part 3 of 3 · Worksheet

Prove it is reliable

Is one success enough?

Reliable means more than lucky

A workflow is reliable when it completes the task for more than one input, not just once. One correct output could be luck; two or more show the build actually holds.

So you test with at least two different inputs and verify each output against the task and a trusted source before you trust the whole chain. Reliability is shown by testing, not assumed.

Hands-on mission · Systems Detectives: iterate and chain

Take your Core workflow, test it to find the weak step, iterate one change at a time, then extend it into a chained multi-step workflow and prove it is reliable. You need: your Core workflow strip, a simulated-AI process card deck, a second set of process cards for the chain, an iteration log with before and after columns, and a trusted answer key.

  1. Run your Core workflow and read the output against the task.
  2. Mark the one box that weakens the output – usually the input.
  3. Change only that box, run again, and log the output before and after.
  4. Add a second process card so your output becomes the input of a new step.
  5. Run the whole chain twice, using two different inputs.
  6. Verify each output against the answer key and record which change made the biggest difference.

🧰 No second card set? Go fully human: one student is process A and another is process B, and A passes their written output to B as B's input – showing the hand-off by hand.

Today's tool · Scratch

Tool for this week: Scratch – an input → process → output build (teacher-operated)

The teacher opens Scratch (offline app or scratch.mit.edu) – no account is needed and work saves as a local .sb3 file. Find the three zones: Blocks (left), Code area (middle), Stage (top right). 1. Decide a simple task, e.g. sort a typed sentence into ‘question’ or ‘statement’. 2. Drag an input block (ask … and wait) to capture the input. 3. Build the process: two or three ‘if’ blocks that apply your rule. 4. Add an output block (say) that reports the result. 5. Click the green flag to run it three times, including one tricky input, and note what happened; the red button stops it. Save with File → Save to your computer as an .sb3 to reopen next week. Stay safe: the teacher operates the tool on the board; students never log in; non-personal data only – type only neutral example words, never names, faces or voices.

Lesson summary

Build it in order, test it, fix one box – then chain it and prove it

Key ideas to remember

  • Building a workflow means putting input, process and output in the right order.
  • A simulated model only answers what is written on it; a real trained model generalises to new inputs.
  • The first output is a draft, not a fact – run the workflow, then verify.
  • Iteration means changing one box at a time so you know what helped.
  • A multi-step workflow chains steps; the join between them is the hand-off. Testing a chain checks that each step completes and the hand-off holds.
  • A build is reliable only when it works for more than one input.

Glossary

Workflow
an ordered set of steps that turns your input into an output.
Simulated model
a stand-in, like a card or lookup table, that only answers items written on it.
Real trained model
a model that learned patterns and can answer inputs it has never seen.
Verify
to check an output against the task and a trusted source before you trust it.
Iterate
to test, change one thing, and test again until it works.
Hand-off
the point where the output of one step becomes the input of the next.
Reliable
the workflow completes the task for more than one input, not just once.
