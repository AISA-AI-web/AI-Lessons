The pieces click together

Until now you have practised four skills in separate lessons: understanding the parts of a workflow, building the steps, checking the output, and using AI responsibly. Today they click together on a single task.

You prepare an input, let a simple classifier process it, read the output, and then check that output against a trusted guide. Core · Part 2 of 3

Run the one task

How does the workflow make a result?

Good data, good classifier

You prepare an input, a simple classifier processes it into a label – Recycle, Compost or Landfill – you record the output, and then you check it. Before you trust a classifier, though, look at the examples it learned from.

Three dataset rules keep it fair: balanced classes – roughly the same number of examples in each group; no repeats – never the same example twice; and a separate test set – always check it on new examples it did not learn from (a train/test split). Messy, one-sided or repeated data makes a classifier that looks fine but fails on real items.

Why it matters

Across the UAE, sorting and recycling systems use classifiers like this to reduce waste – and they only help if their outputs are checked and their data is handled responsibly, just like in your task.

Cross-curricular links

Maths – when you count how many labels are correct ‘out of the total’, write it as a fraction and convert it to a percentage. Science – checking a classifier by changing one thing at a time is a fair test. Language – many UAE classifiers do Arabic–English translation, which links to your language study.

Core · Part 3 of 3 · Worksheet

Confident can be wrong

So do you trust every label?

Check, and keep it safe

A classifier gives every item a label, and it can sound very sure. Sure is not the same as correct. That is why the check step matters: you compare each label with a trusted recycling guide, and if they disagree you fix the label – you verify before you trust.

You also keep the task safe by feeding in only object words – never a person's name, face or voice, which are personal data. Checking and keeping data safe are part of the workflow, not extras added at the end.

Think about it

If the classifier labels a greasy pizza box as Recycle but the guide says Landfill, which one should you trust, and how do you decide?

Hands-on mission · Systems Detectives: sort it and check it

In pairs, run a small three-step waste-sorting workflow with simulated-AI cards, then check every output against a trusted guide and note one responsible choice you made. You need six object-word item cards, the simulated-AI classifier cards, a trusted recycling guide card, a workflow table and a pencil.

  1. Prepare your input: choose six cards, each showing only an object word.
  2. Run the process: pass each card through the simulated classifier for a label.
  3. Record the output: write each item and its label in your workflow table.
  4. Check the output: compare every label with the trusted guide and tick agree or flag disagree.
  5. Correct and note: fix any flagged label using the guide, and mark the one you changed.
  6. Write down one responsible choice you made, such as using only object words.

Lab · Part 1 of 3

Run it end-to-end

Why run the whole batch?

From one example to a full run

In the Core lesson you tried the workflow on a few items. Today you run it end-to-end on ten or more, and you write down every check in a check log. That log is powerful: it turns ‘I checked it’ into real evidence.

You can count how many labels the classifier got right, see which were corrected, and spot patterns – maybe messy or mixed items trip it up most. That count is your workflow's accuracy, and it tells you how much to trust the output.

Why it matters

Recycling and sorting services in the UAE keep improving their systems by logging errors and adding new rules – exactly the run, check and adapt loop you are practising today.

Lab · Part 2 of 3

Read the log

What does your record tell you?

Accuracy and patterns

Your check log is more than a list. Count how many labels matched the trusted guide out of the total, and you have your accuracy – say it as a fraction and a percentage. (Keep the word reliable for a workflow that stays consistent across different inputs.)

Then look for patterns. If the same kind of item keeps getting corrected, that is a weak spot to watch, not bad luck. Reading the log this way is how you judge how reliable the workflow really is.

Cross-curricular link · Mathematics

Take your check log's score, such as 9 out of 12, and convert it to a fraction and then a percentage – the exact fraction-to-percentage skill from maths – to state how accurate your sorting workflow was.

Think about it

If your workflow gets 9 out of 12 right, is that reliable enough to use for real recycling? What would make you trust it more?

Lab · Part 3 of 3 · Worksheet

Add a constraint

How do you improve without starting over?

Adapt, do not restart

A real workflow rarely stays the same – you add rules as you learn. Today you add one constraint: either a second criterion, like labelling each item ‘reusable’ or not, or a risk rule, like flagging any item that might be contaminated. Then you re-check only the items the new rule touches.

Notice that you do not start over – you adapt the workflow you already have. That run-check-adapt loop is called iteration. All the while you keep the safe rules: only object words go in, and every output is verified before you trust it.

Hands-on mission · Systems Detectives: run, log, and adapt

In pairs, run the full sorting workflow end-to-end on ten to twelve items with simulated-AI cards, keep a complete check log, then add one constraint and re-check the items it affects. Account-free, with only object words used.

  1. Select ten to twelve item cards, each showing only an object word.
  2. Run every item through the simulated classifier and record its label in the check log.
  3. Check each label against the trusted guide, tick agree or flag disagree, and write the correction.
  4. Count your accuracy: how many were right out of the total, as a fraction and a percentage.
  5. Add one constraint – a second criterion or a risk rule – and re-check only the items it affects.
  6. Write one sentence on how the constraint changed your workflow and which items needed a second look.

Lesson summary

You ran one task with all four strands – then ran it in full, logged every check and adapted it

Key ideas to remember

  • An AI solution is a pipeline: input, process and output, wrapped in checking and responsible use.
  • Integration means understanding, building, checking and responsible use act on one task together.
  • Good data is balanced, has no repeats, and is tested on a separate set of new examples.
  • A confident label can still be wrong, so you verify it against a trusted guide.
  • Running end-to-end means every stage, in order, on a full batch – and a check log turns ‘I checked it’ into evidence.
  • Accuracy is how many were right out of the total, written as a fraction and a percentage.
  • You improve a workflow by adding a constraint and re-checking – iteration, not a restart.

Glossary

Workflow
the steps a task goes through, from input to process to output.
Classifier
a process that sorts each item into a group, such as Recycle or Compost.
Verify
to check an answer against a trusted source before you trust it.
Personal data
information about a real person, such as a name, face or voice, which never goes into the tool.
End-to-end
running every stage of the workflow in order on a full set of items.
Check log
a table where you record each output and whether the trusted guide agreed.
Accuracy
how often the workflow got the answer right, counted out of the total.
Constraint
a new rule or limit you add, such as a second criterion or a risk to watch for.
